# Power Query CSM-KM — документация

**Версия скрипта:** 2.1  
**Файл:** `OUT/PQ_Script_CSM_KM.pq`  
**Платформа:** Excel 2016 (русская версия), Power Query

---

## 1. Описание задачи

### 1.1. Контекст

На листе **Данные** книги Excel размещены пары смарт-таблиц для загрузки показателей в **СПОД**:

| Таблица данных | Таблица параметров | Связь |
|----------------|-------------------|-------|
| `_data_base1` | `_param_base1` | индекс `1` |
| `_data_base2` | `_param_base2` | индекс `2` |
| … | … | … |
| `_data_baseN` | `_param_baseN` | индекс `N` |

Количество пар **не фиксировано** — достаточно добавить `_data_base6` / `_param_base6`, скрипт подхватит их при обновлении запроса.

### 1.2. Входные данные

**`_data_baseN`** — две колонки:

| Колонка | Описание |
|---------|----------|
| `ТАБЕЛЬНЫЙ НОМЕР` | Идентификатор сотрудника |
| `ПОКАЗАТЕЛЬ` | Факт (число или текст с запятой) |

**`_param_baseN`** — блок key-value (1-я колонка — ключ, 2-я — значение):

| Ключ | Пример | Используется в выходе |
|------|--------|----------------------|
| `CONTEST_CODE` | `01_2026-1_07-5_1` | да |
| `TOURNAMENT_CODE` | `t_01_2026-1_07-5_1_4001` | да |
| `PLAN_VALUE` | `1000000.00000` | да |
| `CONTEST_DATE` | `2026-05-25` | да |
| `CONTEST-DATA=>FULL_NAME` | *(задаётся пользователем)* | да |
| `Бизнес-блок` | `KMKKSB` | нет |

> Чтение параметров **не зависит** от имён колонок «Поле»/«Значение» — всегда берутся 1-я и 2-я колонки таблицы.

### 1.3. Выходные данные (13 колонок)

| № | Колонка | Тип | Формат / источник |
|---|---------|-----|-------------------|
| 1 | `MANAGER_PERSON_NUMBER` | Текст | 20 символов, лидирующие нули |
| 2 | `CONTEST_CODE` | Текст | `_param_baseN` |
| 3 | `TOURNAMENT_CODE` | Текст | `_param_baseN` |
| 4 | `CONTEST_DATE` | Текст | `_param_baseN` |
| 5 | `PLAN_VALUE` | Текст | `_param_baseN` → `PLAN_VALUE`, `0.00000` (**точка**) |
| 6 | `FACT_VALUE` | Текст | `_data_baseN` → `ПОКАЗАТЕЛЬ`, `0.00000` (**точка**) |
| 7 | `priority_type` | Текст | всегда `"1"` |
| 8 | `CONTEST-DATA=>FULL_NAME` | Текст | `_param_baseN`, ключ `CONTEST-DATA=>FULL_NAME` |
| 9 | `ДУБЛЬ` | Текст | кол-во дублей или `"-"` |
| 10 | `СУММА ПО ТАБЕЛЬНОМУ` | Текст | сумма дублей, **запятая**: `381,00000` |
| 11 | `В ФОРМАТЕ` | Текст | та же сумма, **точка**: `381.00000` |
| 12 | `PLAN_VALUE_число` | Число | для расчётов в Excel |
| 13 | `FACT_VALUE_число` | Число | для расчётов в Excel |

### 1.4. Правила преобразования

**Табельный номер:**
```
83790926  →  00000000000083790926
00594932  →  00000000000000594932
```

**PLAN_VALUE** — из `_param_baseN`, строка с ключом `PLAN_VALUE`:
```
1000000.00000  →  PLAN_VALUE = "1000000.00000"
                 →  PLAN_VALUE_число = 1000000
```

**FACT_VALUE** — из `ПОКАЗАТЕЛЬ`:
```
4,7   →  4.70000
187.125 (число)  →  187.12500
```

**Дубликаты** — ключ:
```
CONTEST_CODE + "|" + TOURNAMENT_CODE + "|" + MANAGER_PERSON_NUMBER
```

При дублях:
- `ДУБЛЬ` = `"2"`, `"3"`, …
- `СУММА ПО ТАБЕЛЬНОМУ` = `381,00000` (запятая)
- `В ФОРМАТЕ` = `381.00000` (точка)

Без дублей — `"-"` во всех трёх колонках.

## 2. Откуда берётся PLAN_VALUE

```
_param_base1 (A3:B8)
├── CONTEST_CODE      → CONTEST_CODE
├── TOURNAMENT_CODE   → TOURNAMENT_CODE
├── PLAN_VALUE        → PLAN_VALUE + PLAN_VALUE_число   ← здесь
├── CONTEST_DATE      → CONTEST_DATE
└── CONTEST-DATA=>FULL_NAME → CONTEST-DATA=>FULL_NAME
```

Для каждой строки `_data_base1` значение `PLAN_VALUE` **одинаковое** — берётся из соответствующей `_param_baseN`.

## 3. Архитектура скрипта

```
Excel.CurrentWorkbook()
        │
        ▼
ИмяНачинаетсяС → индексы _data_base* и _param_base*
        │
        ▼
List.Intersect → пары [1, 2, 3, …]
        │
        ▼
ОбработатьПару(индекс) для каждой пары
        │
        ▼
Table.Combine
        │
        ▼
Группировка → ДУБЛЬ, СУММА, В ФОРМАТЕ
        │
        ▼
Итоговая таблица (13 колонок)
```

---

## 4. Ключевые функции

| Функция | Назначение |
|---------|------------|
| `ИмяНачинаетсяС` | Безопасная проверка префикса (имя короче префикса не ломает `Text.Range`) |
| `ИзЗапятойВЧисло` | Парсинг числа без зависимости от русской локали (`1000000.00000`) |
| `ЧислоВТекстСТочкой` | `0.00000` с точкой — PLAN_VALUE, FACT_VALUE, В ФОРМАТЕ |
| `ЧислоВТекстСЗапятой` | `0.00000` с запятой — СУММА ПО ТАБЕЛЬНОМУ |
| `ПолучитьПараметрЗначение` | Поиск по 1-й колонке (ключ), возврат 2-й (значение) |
| `ОбработатьПару` | Обработка одной пары `_data_baseN` + `_param_baseN` |

## 5. Настройки в начале скрипта

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `ФорматЧисла` | `"0.00000"` | Шаблон форматирования |
| `ДлинаТабельногоНомера` | `20` | Длина табельного номера |
| `ЗначениеПриоритета` | `"1"` | `priority_type` |
| `ЗначениеБезДубля` | `"-"` | При отсутствии дубля |
| `ПрефиксТаблицыДанных` | `"_data_base"` | Префикс таблиц данных |
| `ПрефиксТаблицыПараметров` | `"_param_base"` | Префикс таблиц параметров |
| `КлючПараметраFullName` | `"CONTEST-DATA=>FULL_NAME"` | Ключ в `_param_baseN` |
| `КолонкаFullName` | `"CONTEST-DATA=>FULL_NAME"` | Имя выходной колонки |

## 6. Подключение в Excel 2016

1. **Данные** → **Новый запрос** → **Пустой запрос**.
2. **Расширенный редактор** → вставить код из `OUT/PQ_Script_CSM_KM.pq`.
3. **Готово** → переименовать запрос (напр. `СПОД_Сборка`).
4. **Закрыть и загрузить** на лист `СПОД`.
5. В каждой `_param_baseN` добавить строку `CONTEST-DATA=>FULL_NAME` при необходимости.

## 7. Диагностика

| Симптом | Проверка |
|---------|----------|
| Ошибка на `Шаг_03` | В книге есть короткие имена таблиц (`SPOD`, `_t`) — исправлено в v2.1 |
| `PLAN_VALUE` = `0.00000` | Шаг `Шаг_01_Источник` → Content `_param_base1` → строка `PLAN_VALUE` |
| Пустой `CONTEST-DATA=>FULL_NAME` | Добавить ключ в `_param_baseN` |
| `СУММА` с точкой вместо запятой | Обновить скрипт до v2.1 |
