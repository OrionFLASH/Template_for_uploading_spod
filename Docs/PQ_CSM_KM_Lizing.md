# Power Query CSM-KM — Лизинг (FIO / TN)

**Версия скрипта:** 1.0 (на базе CSM-KM v2.1)  
**Файл:** `OUT/PQ_Script_CSM_KM_Lizing.pq`  
**Платформа:** Excel 2016 (русская версия), Power Query

---

## 1. Назначение

Расширение базового скрипта [`PQ_CSM_KM.md`](PQ_CSM_KM.md) для сценария **Лизинг**: часть комплектов данных может поступать не по табельному номеру, а по **ФИО** с последующим преобразованием в табельный через справочник.

Один запрос обрабатывает **смешанные** комплекты: для каждой пары `_data_baseN` / `_param_baseN` режим задаётся параметром `type_ind`.

---

## 2. Параметр `type_ind`

Добавляется в каждую `_param_baseN` (key-value, как остальные параметры):

| Значение | Режим | Колонка в `_data_baseN` |
|----------|-------|-------------------------|
| `TN` | По табельному номеру (как базовый скрипт) | `ТАБЕЛЬНЫЙ НОМЕР` |
| `FIO` | По ФИО с поиском в справочнике | `ФИО` |

Если `type_ind` пустой или отличен от `FIO` — используется режим **TN**.

**Пример блока `_param_base1`:**
```
type_ind              TN
CONTEST_CODE          01_2026-1_07-5_1
TOURNAMENT_CODE       t_01_2026-1_07-5_1_4001
PLAN_VALUE            1000000.00000
CONTEST_DATE          2026-05-25
CONTEST-DATA=>FULL_NAME  ...
```

---

## 3. Справочник ФИО

**Лист:** `FIO`  
**Смарт-таблица:** `_data_fio`

| Колонка | Назначение |
|---------|------------|
| `Клиентский менеджер` | ФИО для поиска (сопоставляется с колонкой `ФИО` в `_data_baseN`) |
| `Код КМ` | Табельный номер, подставляемый в расчёт |

**Логика поиска (режим FIO):**
1. Берётся значение из колонки `ФИО` в `_data_baseN`.
2. Поиск в `_data_fio` по `Клиентский менеджер` (без учёта регистра, с обрезкой пробелов).
3. При совпадении — в расчёт идёт `Код КМ`.
4. При отсутствии совпадения — подставляется **`00000000`** (в `MANAGER_PERSON_NUMBER` дополняется до 20 символов нулями слева).

---

## 4. Выходные колонки (15 колонок)

Базовые 13 колонок из CSM-KM v2.1 **плюс** две служебные в конце:

| № | Колонка | Описание |
|---|---------|----------|
| 1–13 | *(как в базовом скрипте)* | MANAGER_PERSON_NUMBER … FACT_VALUE_число |
| 14 | `FIO` | Исходное ФИО из `_data_baseN` (в режиме TN — `"-"`) |
| 15 | `ТАБЕЛЬНЫЙ НЕ НАЙДЕН` | `"ДА"` — табельный не найден в справочнике; `"-"` — найден или режим TN |

**Полный порядок:**
```
MANAGER_PERSON_NUMBER, CONTEST_CODE, TOURNAMENT_CODE, CONTEST_DATE,
PLAN_VALUE, FACT_VALUE, priority_type, CONTEST-DATA=>FULL_NAME,
ДУБЛЬ, СУММА ПО ТАБЕЛЬНОМУ, В ФОРМАТЕ,
PLAN_VALUE_число, FACT_VALUE_число, FIO, ТАБЕЛЬНЫЙ НЕ НАЙДЕН
```

## 5. Схема обработки

```
_param_baseN.type_ind
        │
        ├── TN ──► _data_baseN.ТАБЕЛЬНЫЙ НОМЕР ──► MANAGER_PERSON_NUMBER
        │          FIO = "-", ТАБЕЛЬНЫЙ НЕ НАЙДЕН = "-"
        │
        └── FIO ─► _data_baseN.ФИО
                    │
                    ▼
               _data_fio (лист FIO)
               Клиентский менеджер → Код КМ
                    │
                    ├── найден ──► Код КМ → MANAGER_PERSON_NUMBER
                    └── не найден ► 00000000, ТАБЕЛЬНЫЙ НЕ НАЙДЕН = "ДА"
                    │
                    ▼
               Сборка СПОД (как базовый скрипт)
```

## 6. Ключевые функции скрипта

| Функция / шаг | Назначение |
|---------------|------------|
| `Шаг_02б_СправочникФИО` | Загрузка `_data_fio`, нормализация ключа поиска |
| `ИзвлечьПараметры` | Чтение `type_ind` и остальных параметров |
| `НормализоватьТаблицуДанных` | Ветвление TN / FIO, формирование MANAGER_PERSON_NUMBER |
| `ОбработатьПару` | Обработка одной пары с учётом режима |
| `Шаг_23_ИтоговаяТаблица` | Финальный порядок 15 колонок |

## 7. Настройки в начале скрипта

| Переменная | Значение | Назначение |
|------------|----------|------------|
| `ИмяТаблицыСправочникФИО` | `"_data_fio"` | Имя смарт-таблицы на листе FIO |
| `КлючПараметраTypeInd` | `"type_ind"` | Ключ режима в `_param_baseN` |
| `ЗначениеTypeIndTN` | `"TN"` | Режим по табельному |
| `ЗначениеTypeIndFIO` | `"FIO"` | Режим по ФИО |
| `ТабельныйЕслиФИОНеНайден` | `"00000000"` | Заглушка при отсутствии в справочнике |
| `КолонкаFIO` | `"FIO"` | Выходная колонка с исходным ФИО |
| `КолонкаТабельныйНеНайден` | `"ТАБЕЛЬНЫЙ НЕ НАЙДЕН"` | Флаг ненайденного табельного |

---

## 8. Подключение в Excel

1. Убедитесь, что на листе **FIO** есть смарт-таблица **`_data_fio`**.
2. В каждую `_param_baseN` добавьте строку **`type_ind`** (`TN` или `FIO`).
3. Для комплектов с `FIO` в `_data_baseN` используйте колонку **`ФИО`** вместо `ТАБЕЛЬНЫЙ НОМЕР`.
4. **Данные** → **Новый запрос** → **Пустой запрос** → **Расширенный редактор**.
5. Вставьте код из `OUT/PQ_Script_CSM_KM_Lizing.pq`.
6. **Закрыть и загрузить** на лист `СПОД`.

---

## 9. Диагностика

| Симптом | Решение |
|---------|---------|
| Все табельные `00000000` в режиме FIO | Проверить совпадение ФИО в `_data_baseN` и `_data_fio` (пробелы, регистр) |
| Ошибка при загрузке справочника | Создать смарт-таблицу `_data_fio` на листе FIO |
| `ТАБЕЛЬНЫЙ НЕ НАЙДЕН` = `ДА` | ФИО отсутствует в справочнике — добавить строку в `_data_fio` |
| Режим TN не работает | Убедиться, что `type_ind` = `TN` и колонка называется `ТАБЕЛЬНЫЙ НОМЕР` |
